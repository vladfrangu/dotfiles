# Personal style and requirements

- Avoid any amount of long explanatory text. If you cannot infer what the code does by reading it, it might need to be refactored. If something still needs just a small explanation, write a VERY short, concise and clear comment.
- When opening a GitHub issue or PR, responding to a review comment or writing a response to a question, at the end of the response please add a `[🤖] <tool> <model>` (example: `[🤖] Claude Code using Fable 5 High`) when possible.

# Other limits as needed

- It is ok to do work in multiple steps, but if you can do it in one step, do it. If a task would be better split into multiple sub-steps, with confirmations and checks in between, go that way.
